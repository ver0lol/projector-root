# projector-root

Удалённое исследование Android 11 мини-проектора **P30 / Allwinner H713M**: идентификация платы, доступ к существующей заводской root-службе, чтение резервных образов и проверка Android Verified Boot.

Это самостоятельный репозиторий про root и загрузочные образы. Интерфейс домашнего экрана находится в отдельном проекте **focal-launcher**.

## Что подтверждено

- OEM модель: `P30_H713_V1.1_CHIHI_emcp`; торговая модель P30 предполагается, маркировка платы не сверена физически.
- Платформа: `sun50iw12p1` / `ares`, строка CPU `QuadCore-H713M`, четыре логических ядра.
- Android 11 / API 30, Linux 5.4.99, приложения `armeabi-v7a` (ARM32).
- Linux видит `MemTotal: 1474000 kB` — около 1,41 ГиБ. Физическая ёмкость памяти отдельно не проверена.
- eMMC: 7 818 182 656 байт, около 7,28 ГиБ (класс 8 ГБ).
- Вывод Android: 1280 × 720, 160 dpi; это не отдельная проверка физической LCD-матрицы.
- Полный root получен через уже работающий factory `qw --daemon`, без установки Magisk, прошивки или программного reboot.
- Рабочий слот `_a`. Сохранённые образы `_b` заполнены нулями.
- Исходные boot-образы проверялись повторным чтением и SHA-256. Подготовленный Magisk-кандидат не устанавливался и не соответствует подписанному stock boot hash.

## Начать без устройства

```sh
python3 scripts/check_repo.py
python3 -m unittest discover -s scripts/qa -p 'test_*.py'
```

Нужны Python 3.9+ и Git. Проверки не используют ADB, интернет, резервные образы или root. Для публикации исходников подключение проектора вообще не требуется.

## Доступ к своему устройству

Скопируйте `config/device.example.json` в игнорируемый `local/device.json` и укажите проверенную идентичность своего проектора. Шаблон намеренно не проходит guard. ADB должен быть установлен отдельно; адрес и серийный номер в публичном репозитории не хранятся.

```sh
python3 scripts/remote_root.py --help
python3 scripts/remote_root.py --check
```

Второй вызов проверяет устройство и существующий daemon; при необходимости создаёт только обычную копию штатного shell в фиксированном временном каталоге. Он не начинает root-службу и не прошивает устройство. Подробности — [REMOTE-ROOT.md](docs/REMOTE-ROOT.md).

## Инструменты

| Файл | Назначение |
| --- | --- |
| `scripts/remote_root.py` | Проверенный доступ к уже работающему factory qw; явные режимы check, shell и command |
| `scripts/device_backup.py` | Чтение образов через проверенную GPT, с CRC, границами и хешами |
| `scripts/inspect_images.py` | Локальная проверка заголовков, размеров и SHA-256 |
| `scripts/verify_avb_constraints.py` | Проверка сохранённых AVB-образов с закреплённым AOSP avbtool |
| `scripts/prepare_magisk.py` | Подготовка исследовательского кандидата, без установки и прошивки |
| `scripts/project_config.py` | Отказ от работы при отсутствующей конфигурации или несовпадении идентичности |
| `vendor/avbtool.py` | Неизменённый AOSP-инструмент с сохранённой лицензией |

Резервные образы, исходный Magisk APK, диагностические журналы и приватная конфигурация остаются вне Git. Поэтому AVB-проверка и подготовка кандидата требуют отдельно полученных собственных образов и указанных в документации инструментов. Не подставляйте образы другого похожего проектора.

## Граница безопасности

**Восстановление после неудачной прошивки не подтверждено.** Этот проект не предоставляет разрешения на запись raw-разделов, разблокировку, изменение AVB, переключение слотов или reboot. Не запускайте новый root daemon. Особые Allwinner USB sysfs-узлы нельзя даже читать: чтение может менять роль USB.

Сначала изучите [AGENTS.md](AGENTS.md), [RECOVERY.md](docs/RECOVERY.md) и [исследование устройства](docs/HARDWARE-RESEARCH.md). Наличие второго слота и factory root не доказывает возможность восстановления.
