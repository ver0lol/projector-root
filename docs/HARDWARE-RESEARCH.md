# projector-root

Рабочий проект для P30_H713_V1.1_CHIHI_emcp. Проверено на локальном Mac 9 ноября 2026 года. **Полный root получен через уже работающую заводскую службу qw по Wi-Fi, без прошивки и reboot.** ADB по локальной сети работал при исследовании; фактический адрес хранится только в приватной конфигурации. Инструкция: [Root без прошивки](REMOTE-ROOT.md), проверка: `python3 scripts/remote_root.py --check`. Исходные образы сохранены; Magisk кандидат не установлен и для найденного способа не требуется. Восстановление после неудачной прошивки всё ещё не подтверждено.

## Материалы исследования

В этом репозитории передаются скрипты и очищенная документация. Описанные ниже образы, журналы, кандидат Magisk и скачанные APK **не входят в Git/архив** и остаются у исходного владельца отдельно. Лаунчер и VPN выделены в самостоятельный **focal-launcher**.

- `backups/` — 18 исходных образов, 328 204 288 байт, плюс обе GPT; оригиналы доступны только для чтения. `manifest.json` хранит геометрию и результаты проверки; `SHA256SUMS` — контрольные суммы.
- `artifacts/boot_a.magisk-v31.1.candidate.img` — кандидат Magisk, 67 108 864 байта. Подробный отчёт, журналы, флаги и разобранные компоненты лежат в `artifacts/magisk-v31.1-boot_a-9725bc440d12d8b9a1fe/`.
- `scripts/device_backup.py` — чтение eMMC по проверенной GPT, инвентаризация и повторяемые резервные копии.
- `scripts/prepare_magisk.py` — подготовка кандидата только в отдельной временной папке; нет установки приложения, root daemon, прошивки или перезагрузки.
- `scripts/inspect_images.py` — локальная проверка размеров, заголовков, компонентов и SHA-256.
- `scripts/verify_avb_constraints.py` — локальная проверка подписей AVB и соответствия хешей исходникам и кандидату.
- `scripts/remote_root.py` — доступ к существующей factory root службе; по умолчанию только проверка прав, есть явные режимы shell и command.
- `docs/REMOTE-ROOT.md` — найденный способ root без прошивки, ограничения и ограничения существующей factory-службы.
- `docs/RECOVERY.md` — условия и процедура восстановления; `docs/MAGISK-SOURCES.md` — источники и особенности Magisk.
- `evidence/` — свойства, таблица разделов, вывод bootctl, результаты анализа AVB и USB. `tools/` — локальные внешние инструменты и APK; публичный avbtool включён отдельно в `vendor/avbtool.py`.

Полная eMMC, super и пользовательские данные не копировались. Сохранён участок до первого GPT раздела, 36 МиБ: он может содержать загрузочные данные Allwinner вне именованных разделов. Это резервная копия, а не готовый PhoenixSuit/FEL образ прошивки.

## Результаты проверки

Оба boot прочитаны полностью дважды; для каждого образа дополнительно совпал SHA-256, вычисленный на проекторе и на Mac. GPT основная и резервная прошли CRC32, совпали друг с другом и с sysfs. В GPT записано нестандартное reserved=1; скрипт фиксирует это отклонение и проверяет все остальные поля и CRC.

| Файл | SHA-256 |
| --- | --- |
| boot_a.img | d4f7c4ebe5dc2d9fc05d20db9bbfe95d3a1dfb62417bb73538e48cabd76fcb70 |
| boot_b.img | 3b6a07d0d404fab4e23b6d34bc6696a6a312dd92821332385e5af7c01c421351 |
| Magisk кандидат | 27c837551d8da3c247263ffaa411d13db431eabc4f11f942e3b296086e1c2865 |

boot_a имеет сигнатуру ANDROID!, header v3, ядро 21 970 604 байта и ramdisk 13 844 960 байт. В кандидате ramdisk 14 090 479 байт; ядро побайтно идентично оригиналу. Magisk ramdisk test возвращает 1, внедрённый init совпадает с проверенным magiskinit из APK. Действующий boot_a после подготовки имеет прежний SHA-256.

**boot_b и все сохранённые разделы с суффиксом _b полностью заполнены нулями. Переключать слот нельзя.** bootctl ошибочно с практической точки зрения сообщает оба слота bootable; наличие имён и этот флаг не означают наличие рабочих образов.

Подписи встроенными ключами в vbmeta_a, vbmeta_system_a и vbmeta_vendor_a проверены. Их общий digest совпал с `ro.boot.vbmeta.digest` работающего устройства. Хеши stock boot, vendor_boot и dtbo соответствуют дескрипторам. У vbmeta_a SHA256_RSA2048 и flags=0. **Кандидат не соответствует подписанному stock boot hash.** Это ожидаемое следствие патча; при реально применяемой AVB образ будет отклонён. Доверие аппаратного загрузчика к встроенному ключу и его фактическую политику эти проверки не доказывают.

## Magisk

Использован официальный [Magisk 31.1](https://github.com/topjohnwu/Magisk/releases/tag/v31.1), APK SHA-256 `89cefac0a318afa39fb3880c45c87b036c05bc1ebf02a7a715b7f8d7c26ac6e7`. Android 11 и ARM32 поддерживаются; работа patch toolchain на этом проекторе подтверждена выполнением. Совместимость загрузки патча ещё не проверена.

Флаги кандидата: KEEPVERITY=true, KEEPFORCEENCRYPT=true, PATCHVBMETAFLAG=false, RECOVERYMODE=false, LEGACYSAR=false; PREINITDEVICE=metadata. Штатный boot_patch.sh из APK не изменялся; изолирующая оболочка заменяет только вывод и аварийное завершение, чтобы не затрагивать `/dev/tmp`. Сообщения `Failed to patch` в журнале относятся к отсутствующим шаблонам необязательных Samsung kernel patches; сравнение ядра подтвердило отсутствие изменений.

Временная папка Magisk подготовки: `/data/local/tmp/projector-root-9725bc440d12d8b9a1fe`. Она содержит обычные файлы; приложение Magisk не устанавливалось, Magisk daemon не запускался. Для factory доступа добавлена копия штатного sh в `/data/local/tmp/projector-root-remote-20261109/.agingdragonbox`. Использовалась уже работавшая qw служба; новый daemon не устанавливался и не запускался. Роли USB и свойства загрузки не менялись.
