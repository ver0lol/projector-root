# Восстановление P30 H713

Сейчас восстановление после неудачной загрузки **не подтверждено**. Резервные копии корректны, но ADB по сети доступен только пока работает Android. USB fastboot, FEL, аппаратная кнопка входа и подходящая прошивка именно этой платы не проверены. Поэтому прошивку кандидата, изменения AVB, разблокировку, смену слота и reboot выполнять нельзя.

## Что известно о USB

По сообщению владельца, снаружи есть только USB «мама». В Android существует UDC `4100000.udc-controller`, состояние `not attached`, максимум high-speed. В device tree включены usbc0 и udc. Vendor init содержит переключение между USB host и device по `persist.sys.usb0device`; текущее значение 0. Это говорит о возможностях прошивки, но не устанавливает разводку наружного разъёма и доступность аварийного режима.

Некоторые sysfs узлы Allwinner меняют USB роль даже при чтении: vendor init использует `copy .../usb_device /dev/null` и `copy .../usb_host /dev/null`. Эти узлы не читались, роли и свойства не менялись. Нельзя использовать их как обычную диагностическую информацию. Не соединяйте Mac и непроверенный host порт кабелем USB-A ↔ USB-A: сначала нужна подтверждённая схема сервисного соединения конкретной платы.

## Что нужно установить до первой записи

1. Маркировку платы и соответствие OEM `P30_H713_V1.1_CHIHI_emcp`, boot device `h713m-tuna_p3`, сборка `hxws10161629`.
2. Физический сервисный путь, независимый от Android: подтверждённые порт, кабель, питание, способ входа в fastboot/FEL и способ возврата. Вход в другой режим требует отдельного согласия владельца даже без записи.
3. Что сервисный инструмент поддерживает именно этот SoC/DDR/накопитель, видит правильную геометрию и способен восстановить исходный boot_a. Чужая инструкция HY300 или один VID/PID этого не доказывают.
4. При необходимости FEL — подходящую и проверенную board specific DDR initialization и совместимый инструмент. Raw дампы разделов нельзя передавать PhoenixSuit как заводской образ. Полной eMMC копии сейчас нет.
5. Политику загрузчика: `locked` и подписанный boot hash требуют отдельного решения. Подготовленный патч нарушает штатный hash. Отключение AVB, прошивка vbmeta или unlock сейчас не разрешены; стандартный unlock Android может стереть данные.
6. Стабильное питание, локальные копии исходных файлов и явное согласие владельца на конкретную запись и отдельную перезагрузку.

## Точная цель восстановления

Если в будущем изменялся только boot_a, возвращать нужно **только исходный boot_a**, не весь диск и не обе копии boot. Никогда не копировать нулевой boot_b на boot_a и не переключаться на B.

| Поле | Значение из проверенной GPT |
| --- | --- |
| GPT имя | boot_a |
| Нода Android | /dev/block/mmcblk0p5 |
| Диапазон секторов | 205824–336895, сектор 512 байт |
| Смещение в eMMC | 105381888 байт |
| Размер | 67108864 байта |
| Исходный файл | backups/boot_a.img |
| SHA-256 | d4f7c4ebe5dc2d9fc05d20db9bbfe95d3a1dfb62417bb73538e48cabd76fcb70 |

Если менялись vbmeta, slot metadata, bootloader или другие разделы, восстановления одного boot_a недостаточно. Нужен отдельный план по списку реально сделанных изменений.

## Условная процедура через fastboot

Этот маршрут ещё не проверен и сейчас не разрешён к исполнению. Сначала необходимо выполнить все условия выше. Не существует разрешения автоматически перейти к записи после ответа «продолжай».

1. На Mac в корне проекта проверить оригиналы:

```sh
(cd backups && shasum -a 256 -c SHA256SUMS)
```

2. После отдельного разрешения на смену режима войти в физически доступный fastboot и провести только чтение: `fastboot devices -l`, затем для обнаруженного **USB** serial проверить product, current-slot и partition-size:boot_a. Нельзя использовать сетевой адрес ADB как fastboot serial или автоматически выполнять unlock при отказе доступа.
3. Сверить идентичность платы, слот a, размер `0x4000000` и наличие именно цели boot_a. Если bootloader не сообщает геометрию или не поддерживает boot_a, остановиться; не подбирать псевдоним boot наугад.
4. Только после доказанного восстановления и отдельного согласия владельца потенциальная команда возврата оригинала имеет вид:

```text
fastboot -s <ПРОВЕРЕННЫЙ_USB_SERIAL> flash boot_a backups/boot_a.img
```

Команда приведена как шаблон в тексте; автоматического скрипта записи в проекте нет. При запрете записи locked bootloader не обходить его разблокировкой без нового плана и согласия.

5. Проверить результат записи и, если реализация позволяет, прочитать образ обратно до reboot. Перезагрузка требует отдельного согласия. После нормальной загрузки сравнить полный SHA-256 boot_a с исходным и подтвердить текущий слот и ADB.

При неудачной загрузке нельзя бесконечно выключать питание или перебирать слоты. Использовать только заранее проверенный сервисный маршрут. FEL, UART и прямое программирование eMMC требуют собственного проверенного плана; сейчас готовых команд записи для них нет.

## Основания

- [Magisk installation](https://topjohnwu.github.io/Magisk/install.html): патч собственного образа на целевом устройстве; требование unlocked bootloader.
- [AOSP AVB](https://android.googlesource.com/platform/external/avb/+/master/README.md): boot hash может храниться в отдельной подписанной vbmeta.
- [AOSP A/B implementation](https://source.android.com/docs/core/ota/ab/ab_implement): работоспособность альтернативного слота зависит от полного набора образов и metadata.
- [AOSP locking and unlocking](https://source.android.com/docs/core/architecture/bootloader/locking_unlocking): unlock меняет модель доверия и предполагает очистку пользовательских данных.
- [Первичное исследование другого H713 устройства](https://github.com/YuujiLab/HY300-H713-Research/blob/main/Boot/FASTBOOT_RESEARCH.md): подтверждает необходимость проверять dummy slots, но не устанавливает совместимость восстановления этой P30 платы.
