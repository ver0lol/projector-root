# Свой проект на GitHub с Arch Linux

Git сохраняет версии проекта на компьютере. GitHub даёт проекту страницу в интернете: README, скриншот, историю и ссылку, которой можно поделиться. GitHub Desktop не требуется. Агент с доступом к терминалу может выполнить технические шаги; владелец входит в свой аккаунт через браузер.

Подключать проектор, получать root, устанавливать Android SDK или собирать APK для публикации не нужно.

## Сначала вход

1. Распакуй архив целиком, сохранив скрытую `.git` в каждой папке. Агент сначала читает README, AGENTS.md и [OWNER_SETUP.md](../OWNER_SETUP.md).
2. Агент проверяет наличие Git, Python и `gh`, затем `gh auth status`. На Arch пакет CLI называется [github-cli](https://archlinux.org/packages/extra/x86_64/github-cli/); устанавливать недостающие системные пакеты следует только обычным разрешённым способом. Не запускать полное обновление системы ради публикации.
3. Если входа нет, агент запускает `gh auth login --hostname github.com --git-protocol https --web` и просит владельца завершить вход в браузере. Пароль, токен и коды подтверждения не отправляются в чат. Вход на сайт сам по себе не даёт терминалу права на push: дождитесь завершения CLI-авторизации. [Официальная инструкция входа](https://cli.github.com/manual/gh_auth_login).
4. Проверьте активный аккаунт: это должен быть GitHub владельца, а не отправителя архива. При доступном GitHub-инструменте агента можно использовать его вместо CLI, если он умеет публиковать репозиторий целиком с историей.

## Перед отправкой исходников

Владелец указывает имя для коммитов и точный verified email или noreply из GitHub Settings → Emails. Затем агент выполняет `scripts/set_owner.py` в обеих папках по [OWNER_SETUP.md](../OWNER_SETUP.md). Это нужно сделать до remote и новых изменений. Проверьте автора и коммитера через `git log -1 --format=fuller`.

Выберите видимость: Public виден всем, Private — владельцу и приглашённым. Значения ключей, VPN-профилей, firmware backup и исходные APK не входят в комплект и не нужны для GitHub. Не добавляйте их через `git add -f`.

## Публикация

После входа, оформления автора и выбора видимости агент создаёт два репозитория в личном аккаунте владельца: `projector-root` и `focal-launcher`. Пример для публичных проектов из папки, содержащей оба репозитория:

```sh
gh repo create YOUR_LOGIN/projector-root --source ./projector-root --remote origin --public --push
gh repo create YOUR_LOGIN/focal-launcher --source ./focal-launcher --remote origin --public --push
```

`YOUR_LOGIN` заменяется проверенным логином владельца; для приватных проектов выбирается `--private` вместо `--public`. Не запускайте оба варианта. [Публикация существующей локальной папки через gh](https://cli.github.com/manual/gh_repo_create).

Не создавайте новый README или лицензию на сервере поверх существующих исходников. Если такое имя уже занято в своём аккаунте, агент сначала изучает ситуацию; не удаляет репозиторий и не делает force-push. Архив нельзя загружать как единственный файл проекта, а `.git` нельзя загружать через веб-форму: Git отправляет историю сам.

## Проверить и найти потом

Агент открывает реальные полученные URL и сверяет владельца, README, скриншот focal-launcher и автора первого коммита. Не придумывает ссылки до публикации.

Завтра их можно найти в GitHub: свой профиль → Repositories → нужный проект. README находится прямо на главной странице, список файлов — выше, история — по ссылке на коммиты. Можно закрепить проекты в профиле.

Для следующих изменений: агент меняет файлы → вы смотрите diff → commit сохраняет новую версию локально → push отправляет её на GitHub. Обе команды агент может выполнять в вашей задаче. Если у чата нет доступа к терминалу, он должен честно это сказать и давать короткие шаги, а не изображать выполненную работу.

Сначала публикуются исходники. APK-релизы можно обсудить позже. Для совместимого обновления установленного лаунчера нужен оригинальный приватный ключ подписи, который передаётся отдельно и никогда не выкладывается на GitHub.
