# Перед первой публикацией

В архиве уже есть полноценный Git-репозиторий и один служебный стартовый коммит. Его автор — `Project Owner <handoff@example.invalid>`. Это техническая заготовка, а не учётная запись отправителя или твой GitHub-профиль.

До добавления remote и публикации попроси своего агента выполнить из каждой папки:

```sh
python3 scripts/set_owner.py --name "Твоё имя" --email "Точный email из настроек GitHub"
```

Лучше использовать точный `noreply` адрес из **GitHub → Settings → Emails**, чтобы личная почта не была видна в коммитах. Не придумывай этот адрес по логину. [Как GitHub связывает email и коммиты](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address).

Сначала можно добавить `--dry-run`. Скрипт меняет имя и email только в настройках этого репозитория, затем автора и коммитера единственного служебного коммита. Исходные файлы и лицензии не меняются. Никакого соединения с GitHub и `force push` нет. При наличии remote, тегов, дополнительных коммитов или изменений файлов скрипт отказывается работать.

Если Python отсутствует, агент может сделать то же обычными командами Git после проверки, что это именно один неопубликованный служебный коммит без remote:

```sh
git config --local user.name "Твоё имя"
git config --local user.email "Твой проверенный email или GitHub noreply"
git -c commit.gpgsign=false commit --amend --reset-author --no-edit
```

После этого проверь `git log -1 --format=fuller` и публикуй репозиторий. Изменения email в Git-конфиге без amend не меняют автора уже существующего коммита.

Это оформление переданного тебе проекта в своём аккаунте. Авторство и лицензии сторонних компонентов AOSP, SagerNet/sing-box и других upstream-проектов сохраняются. Для обычных следующих коммитов этот скрипт больше не нужен. Уже опубликованную историю переписывать не следует.
